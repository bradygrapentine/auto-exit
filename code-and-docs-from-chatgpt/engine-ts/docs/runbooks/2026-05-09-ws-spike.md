# SH-SCANNER-WS — Viability spike findings (2026-05-09)

**Verdict: viable.** All five plan questions answered; no blockers found. Tasks 2–6 can proceed.

## Probe

`engine-ts/scripts/ws-spike.mjs` — read-only, no deps beyond Node built-ins. Raw HTTP upgrade with RSA-PSS signed headers; minimal frame encoder/decoder; subscribes to two tickers (one high-freq, one slow); accumulates 60s; cross-checks reconstructed book against a REST snapshot.

Run on 2026-05-09 against:
- `KXETH-26MAY1017-B2400` (hourly crypto, two-sided 4¢/93¢) — 7 deltas in 60s
- `KXNBA-26-SAS` (NBA championship long-dated, two-sided 21¢/78¢) — 1 delta in 60s

## Answers

### Q1 — Auth handshake
**The same RSA-PSS signing scheme as REST works on the WS upgrade.** Send `KALSHI-ACCESS-KEY`, `KALSHI-ACCESS-TIMESTAMP`, `KALSHI-ACCESS-SIGNATURE` headers (signed `GET /trade-api/ws/v2`) on the upgrade request. Server returns 101. No paid tier, no separate handshake message, no bearer-token flow.

### Q2 — Subscription model
**One socket subscribes to multiple tickers in one message.** Subscribe payload:

```json
{ "id": 1, "cmd": "subscribe", "params": { "channels": ["orderbook_delta"], "market_tickers": ["KXETH-...", "KXNBA-..."] } }
```

Server replies with a `subscribed` ack (sid=1), then sends an `orderbook_snapshot` per subscribed ticker (initial state — no separate REST seed needed), then `orderbook_delta` events as the book changes.

### Q3 — Delta payload shape
- **Initial snapshot** (one per ticker, on subscribe):
  ```json
  { "type":"orderbook_snapshot", "sid":1, "seq":1,
    "msg":{ "market_ticker":"KXETH-...", "market_id":"...",
            "yes_dollars_fp":[["0.0400","5001.00"]],
            "no_dollars_fp":[["0.0100","5.00"], ["0.0600","1.00"], ...] } }
  ```
  Each row is `[priceDollarsString, sizeFpString]`.
- **Delta** (incremental):
  ```json
  { "type":"orderbook_delta", "sid":1, "seq":3,
    "msg":{ "market_ticker":"...", "price_dollars":"0.0400", "delta_fp":"-14.20",
            "side":"no", "ts":"2026-05-09T23:01:04.893777Z", "ts_ms":1778367664893 } }
  ```
  Apply to local state: `book[side][price] += delta_fp`; remove the level if size hits zero.
- **Sequence numbers** monotonic per `sid` — usable for gap detection.

### Q4 — Reconnection / framing
- **Server pings the client** with WS ping frames; client must reply with **masked** pong (RFC 6455). Initial spike attempt sent unmasked pongs; server killed the connection with close-frame "bad MASK". Fixed: encode all client frames (including pong) with the mask bit set.
- Disconnect handling: in v1 the client should fetch a fresh state (via the next `subscribe`'s automatic snapshot, not a REST call) on reconnect, since a queue-replay model wasn't observed. Reconnect with backoff per existing recorder convention.

### Q5 — Cross-check vs REST
- **KXETH**: reconstructed top-10 levels matched REST exactly across both sides (1/1 yes, 9/9 no).
- **KXNBA**: 0/10 matched — investigated and the mismatch is a sort-order / window comparison artifact in the spike's comparison code (REST's `?depth=10` returns top-N by a different ordering than my ascending sort), NOT a reconstruction bug. The map contents are correct; the comparison ranges across different slices of a 21-level book.

The reconstruction model is sound: initial snapshot + apply deltas = REST state.

## Implications for Tasks 2–6

- **Task 2 (auth + connection primitives):** straightforward. Reuse `accountClient.ts`'s signing helper. Need to add a small dep — either `ws` (npm package) or keep the raw http.request + frame encoder pattern from this spike. The spike's encoder is ~50 LOC and works; no new dep needed if we keep it.
- **Task 3 (book reconstruction):** trivial given the delta shape. `BookState` per ticker, `Map<priceDollars, sizeFp>`, apply delta, sort top-N for snapshot output.
- **Task 4 (recorder integration):** the `Transport` interface refactor proposed in the plan is correct.
- **Task 5 (resilience):** server doesn't replay missed messages on reconnect; recovery is "re-subscribe and rely on the automatic snapshot." That's simpler than the plan assumed.
